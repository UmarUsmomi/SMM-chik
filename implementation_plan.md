# План исправления публикации цитат в Telegram

## Цель

Гарантировать, что подтверждённая прямая цитата из новости сохраняется в
опубликованном Telegram-посте с обложкой и отображается как раскрываемая
блочная цитата. Одновременно устранить ошибки, выявленные в этом пути, без
добавления внешних зависимостей и без изменения схемы данных.

## Основания

- Telegram Bot API поддерживает HTML-тег `<blockquote expandable>`.
- Лимит подписи фотографии — 1 024 символа после разбора HTML-сущностей.
- Текущий код случайно запрещает цитаты для части длинных новостей и всегда
  запрещает их для коротких; при сокращении подписи удаляется её конец, где
  обычно находится цитата.

## Решения

1. Сохранять любую цитату, созданную на основе исходной новости, через
   humanizer: если модель удаляет маркер, возвращать оригинальный блок.
2. Не придумывать цитаты в publisher: он отвечает только за безопасную
   передачу уже сформированного блока Telegram.
3. При сокращении подписи сохранять целые блоки `<blockquote>` и удалять
   обычный текст прежде них. Подпись проверяется по UTF-16 после удаления HTML
   разметки и декодирования сущностей.
4. Добавить регрессионные тесты для короткой новости с цитатой, длинной
   подписи с цитатой и корректного лимита Telegram.

## Риски и защита

| Риск | Защита |
| --- | --- |
| Модель выдумывает слова | Прямо запрещать выдуманные цитаты; блок разрешён только если исходник содержит явную цитату. |
| HTML ломается при сокращении | Сокращать HTML-осведомлённо и проверять закрытие тегов тестом. |
| Caption превышает лимит из-за emoji/entities | Считать отображаемый текст в UTF-16 после разбора сущностей. |
