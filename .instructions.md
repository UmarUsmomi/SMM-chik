# SMM Automator Project Instructions

Follow these rules for all future code edits and feature development in this repository:

## 1. Spec-Driven Development (SDD)
- Before making any code changes, always create or update an `implementation_plan.md` outlining the requirements, acceptance criteria, and proposed changes.
- Never write code directly based on conversational prompts without a structured task checklist in `task.md`.

## 2. Session Hygiene
- Do not let sessions exceed 15-25 user turns to prevent context degradation.
- Suggest starting a new session immediately if the task focus shifts (e.g. from scrapers to image processing).

## 3. Database Connection Safety
- Never leave database connections open. Always use contextvars safely and call `db.close_current()` at the end of execution.
- In FastAPI endpoints or background tasks, ensure that the middleware or a `finally` block closes the request connection to prevent client connection exhaustion.

## 4. Telegram API Constraints
- **Caption Limit**: Telegram limits image captions to strictly **1024 characters**.
- **UTF-16 Calculation**: Emojis and special symbols count as 2 UTF-16 code units. Always calculate length using:
  `len(text.encode('utf-16-le')) // 2`
- **Formatting**: Use whitelisted HTML tags (`<b>`, `<i>`, `<code>`, `<pre>`, etc.). Stripping tags like `<blockquote>` is preferred to maintain a clean layout per user request.

## 5. Automated Testing & Verification
- Run `pytest` on all tests (`python -m pytest`) before pushing code to Git.
- Maintain test coverage for any new features or endpoints.
- Ensure tests do not leak database side-effects (clear/mock database path correctly).
